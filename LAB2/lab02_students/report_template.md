# Отчёт по ЛР2

Индивидуальная работа. Объём: 1–2 страницы, максимум 2. Без титульного листа, ФИО и раздела о вкладе. Только техническое содержание. Полные материалы приложите отдельными файлами.

## 1. Взаимодействие LLM и инструментов

Одна схема и 4–6 предложений: модель и способ подключения (локальный сервер или API), входные данные LLM, формат выбранного действия, вызов инструмента, возврат ответа, проверка результата и остановка. Покажите, как обрабатываются ошибки. Здесь опишите собственную реализацию.

## 2. Основные результаты

| Режим | Успехи / всего | Вызовы LLM / эп. | Токены / эп. | p50 / p95, с |
|---|---|---|---|---|
| fixed | … / … | … | … | … / … |
| agent | … / … | … | … | … / … |

Вызовы и токены усредняются по всем эпизодам. p50 — медианное время, p95 — 95-й процентиль. Укажите 1–2 главных различия по пяти классам задач. При известном тарифе добавьте стоимость успешного решения. scripted показывайте отдельно от LLM. Полные метрики и разбивку приложите в CSV.

## 3. Сбои и проверка результата

Три сбоя по 2–3 строки: case_id, первое неверное действие и ответ инструмента, последствия, исправление и результат проверки. Хотя бы один пример объясняет различие fixed и agent. Если своих сбоев мало, используйте ReplayPolicy. Рядом укажите путь к полной трассе.

В 1–2 предложениях назовите дефекты, которые ловят пять негативных проверок. Сами проверки приложите кодом.

## 4. Выводы

3–5 предложений: где агентный выбор помог, сколько ресурсов потребовал, что осталось проблемой и какими задачами ограничен вывод.

## Отдельные файлы в архиве

Код и проверки; agent_prompt.txt и prompts.md; results.csv, summary.csv и полная разбивка; run_config.json; журналы всех эпизодов; README с окружением и командами. В prompts.md укажите использованную помощь ИИ и способ проверки. Эти файлы не входят в объём отчёта.
