# Внешние сценарии

`gpt.json` и `deepseek.json` — неизменённые исходные наборы. `results.json` — последний запуск `run_external_scenarios.py`; в каждом сценарии создана собственная временная база. Использована Qwen2.5-1.5B-Instruct Q4_K_M через локальный llama-server.

Адаптации в тестовом стенде:

- В LONG-01 разворачиваются `text_generation` и `text_suffix`; ранее отправлялось только начало сообщения.
- В MULTI-02, MULTI-04, STALE-03, FAULT-03 и STALE-05 к заявке о HDMI-проекторе добавлено явное наличие HDMI у ноутбука: вход проектора сам по себе не определяет выход ноутбука.
- В S24 отключён штатный USB-C → HDMI переходник: иначе обратный переходник не нужен и ожидаемый `unavailable` противоречит исходному каталогу.
- В S26 отключён штатный HDMI-проектор: иначе прямое подключение доступно и ожидаемый `unavailable` некорректен.
- Для S32 ответ на первую доставку не требуется: процесс действительно завершается после записи и до ответа. Второй ответ должен содержать первоначальную запись. То же проверяется в FAULT-02.
- В S34 одинаковые идентификаторы корректно обрабатываются как повторная доставка; в S35 выполняется повтор после восстановления.
- Другие события перезапуска в этом стенде создают новый экземпляр системы с тем же состоянием в том же процессе. Реальный перезапуск процесса дополнительно проверяют открытые тесты.

Стенд автоматически проверяет допустимые статусы, заполнение полей, соответствие `reserved` базе, отсутствие изменений бронирований на остальных ходах, наличие предыдущего предложения и совпадение комплекта при новой брони, совместимость и наличие предлагаемых позиций, ID после аварии и повтор чтения каталога. Проверка не интерпретирует все текстовые `invariants`, `failure` и `reply` из исходных JSON; их нужно дополнительно проверять вручную. Результат `pass` относится именно к перечисленным автоматическим проверкам, а не подтверждает каждый пункт сценария.

Статистика не является независимой оценкой: набор использовался при разработке и настройке системы. Сценарии также частично дублируются; 79 — количество сценариев, а не независимых типов атак.

`../holdout_scenarios.py` содержит отдельные 12 сценариев с эталонами порта, статуса, состава комплекта и изменений SQLite на каждом ходе; `holdout_results.json` содержит ответы и снимки базы. Он также проверяет наличие идентификаторов в ответе, признаки ложного сообщения о броне и формальную форму уточнения. Это эвристики, а не полноценная смысловая проверка текста. Первоначальный результат составил 7/12; после исправления найденных ошибок — 12/12. Теперь этот набор также использовался для доработки и не является независимым аудитом.

Запуск при включённом сервере:

```bash
MAS_LLM_URL=http://127.0.0.1:8080/v1 MAS_LLM_MODEL=qwen25-1.5b MAS_LLM_TIMEOUT=120 \
  conda run --no-capture-output -n slop python run_external_scenarios.py
```
