# Технический пилот C/M с окном 16384

Цель — проверить адаптер, размеры запросов, бюджет и среду до итоговой
заморозки. Это не финальные результаты и не основание подбирать решения
под C/M. Модель Qwen3.5-4B, thinking выключен, общий бюджет 60000.
Снимки в этой папке относятся только к техническому пилоту.

Команды из корня mas_lr4:

```bash
python -m maslab freeze --config docs/extra_config.json --out runs/pilot_protocols/extra_freeze.json
python -m advanced freeze --out runs/pilot_protocols/advanced_freeze.json
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m maslab run --config docs/extra_config.json --freeze runs/pilot_protocols/extra_freeze.json --split extra --ids C01 --architectures single,fixed,coordinator --budgets 60000 --repeats 1 --out runs/extra_technical_pilot
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m advanced run --freeze runs/pilot_protocols/advanced_freeze.json --ids M01,M04 --architectures single,fixed,coordinator --budgets 60000 --repeats 1 --out runs/advanced_technical_pilot
```

## Результаты

Все 9 запланированных эпизодов имеют result.json; ни один не перезапускался.

| Задача | single | fixed | coordinator |
|---|---|---|---|
| C01 | model_error, HTTP 400 | unfinished | budget_exhausted |
| M01 | model_error, HTTP 400 | budget_exhausted | budget_exhausted |
| M04 | model_error, HTTP 400 | model_error, HTTP 400 | model_error, HTTP 400 |

В C01 итоговый код каждой схемы проходит 3/6 открытых проверок.
В M01 итоговый код каждой схемы проходит 0/12. В M04 допустимый ответ
не сформирован. Это ограниченный технический пилот; закрытая правильность
M04 вообще не оценивается этим стендом. Не смешивать эту таблицу с финальными
таблицами. В эпизодах model_error стенд помечает полный usage неизвестным;
известные токены не заменяют полный расход.

## Диагностика контекста

advanced doctor подтвердил доступность sandbox. До генерации /tokenize показал:
M01 — 8173 входных токена, M04 — 7327. При max_output_tokens=6000 начальные
запросы помещались в 16384, но история/ответы инструментов увеличили вход.
Ниже размеры отклонённых запросов, измеренные отдельно через /tokenize
без повторной генерации и без подмены результатов эпизодов:

| Эпизод | Вход | Запрошенный выход | Всего |
|---|---:|---:|---:|
| C01_single | 13445 | 2951 | 16396 |
| M01_single | 18426 | 6000 | 24426 |
| M04_single | 26171 | 6000 | 32171 |
| M04_fixed | 26194 | 6000 | 32194 |
| M04_coordinator | 26310 | 6000 | 32310 |

Все эти запросы превышают текущее серверное окно 16384. Сохранять это окно
для финального сравнения означало бы систематически измерять инфраструктурные
ограничения. Следующий шаг — поднять сервер с большим окном и провести
отдельный технический пилот при прежних бюджетах/политиках/данных.
Окно 32768 покрывает перечисленные запросы, но для M04 оставляет всего
458 токенов запаса; поздние запросы могут потребовать больше. Если память
позволяет, окно 65536 даст больший запас. Вместимость нужно подтвердить
запуском vLLM; успешный старт на 65536 не предполагается заранее.

В ходе пилота алгоритмы и инструкции по результатам C/M не менялись.
Общая инструкция maslab ранее уточнена на dev; advanced использует собственный
неизменённый BASE. Итоговый core/test и полные C/M не запускались.
