# Технический пилот C/M с окном 65536

Сервер /v1/models подтвердил max_model_len=65536. Модель Qwen3.5-4B,
thinking выключен, бюджеты C/M по 60000, один повтор. Все 9 эпизодов завершены
и сохранены отдельно от пилота 16384. Код, инструкции, конфигурации и снимки
пилота не менялись; изменилось только серверное окно.

```bash
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m maslab run --config docs/extra_config.json --freeze runs/pilot_protocols/extra_freeze.json --split extra --ids C01 --architectures single,fixed,coordinator --budgets 60000 --repeats 1 --out runs/extra_technical_pilot_65k
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m advanced run --freeze runs/pilot_protocols/advanced_freeze.json --ids M01,M04 --architectures single,fixed,coordinator --budgets 60000 --repeats 1 --out runs/advanced_technical_pilot_65k
```

## Результаты и контекст

HTTP 400/model_error больше нет, весь usage известен. Ни один процесс
не завершился успешно: восемь budget_exhausted, C01_fixed — unfinished.
На C01 открытые проверки: single 3/6, fixed 4/6, coordinator 2/6.
В M04 ни одна схема не сформировала допустимый ответ; schema_valid=false.
Закрытая правильность реестра не оценивалась.

Расход M04_single — 105077 токенов, M04_fixed — 105100 при лимите 60000.
Это предусмотренное поведение счётчика: входная история тоже оплачивается,
ответ учитывается целиком, но действие за бюджетом не применяется. Нельзя
подменять фактический расход лимитом или считать неизвестные токены нулём.

## Выявленная несовместимость среды M01

Все M01 получили 0/12. Проверка реальных отчётов выявила инфраструктурный
дефект среды: импорт dataclasses из стандартной библиотеки завершается
PermissionError для /home/owmtgf/anaconda3/lib/python3.11/dataclasses.py.
Ограничение Landlock разрешает /usr, /lib, /lib64, публичный проект и несколько
файлов worker, но не путь стандартной библиотеки Anaconda в домашнем каталоге.
Это происходит до выполнения solve и не является оценкой логики решения.
Модель видела эти ошибки в проверках и расходовала бюджет, поэтому нельзя
просто пересчитать итоговые программы в другой среде и объявить эпизоды
исправленными: нужен новый отдельно обозначенный технический запуск.

advanced doctor эту проблему не обнаруживает: его пример не импортирует
dataclasses. Системный /usr/bin/python3 (3.10.12) с той же изоляцией успешно
импортирует исходный проект M01 и получает предметные результаты, а не
PermissionError. Однако требования M указывают Python 3.11+, поэтому Python
3.10 не выбран как итоговая среда. Для сохранённой модельной правки при такой
диагностике также наблюдался ImportError отсутствующей функции release —
ошибки модельного кода есть наряду с инфраструктурной проблемой.

Sandbox, worker и исполнитель в ходе диагностики не изменялись, изоляция
не отключалась. До итоговой заморозки M нужно обеспечить Python 3.11+,
стандартная библиотека которого доступна при текущей изоляции, либо явно
исправить учёт пути стандартной библиотеки в sandbox и раскрыть изменение.
Эти результаты и прежние пилоты сохранить. Итоговые 696 эпизодов не запущены.
