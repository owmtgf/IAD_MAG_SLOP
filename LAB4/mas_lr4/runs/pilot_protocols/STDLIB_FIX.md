# Исправление доступа к стандартной библиотеке и повторный M-пилот

До исправления Python 3.11 из Anaconda не мог импортировать dataclasses
после включения Landlock: stdlib находится в домашнем каталоге, а список
разрешённых путей учитывал только системные /usr, /lib, /lib64.

## Изменение и проверка

В advanced/sandbox.py к разрешённым для чтения путям добавлены существующие
каталоги stdlib/platstdlib, определённые sysconfig текущего интерпретатора.
Не добавлялись домашний каталог, корень окружения или рабочая папка целиком.
Правила записи, seccomp и ограничения сети/процессов сохранены.
Это разрешает чтение содержимого указанных библиотечных каталогов, включая
вложенные каталоги; список разрешённых Python-модулей отдельно не вводился.

advanced/executor.py: probe теперь импортирует dataclasses в изолированном
worker и проверяет результат, чтобы doctor выявлял такую несовместимость.
Проверены 63 offline-теста. Шесть новых тестов реально запускают worker:
проверка doctor, импорт dataclasses/decimal, запрет внешнего чтения, запрет
записи в проект, запрет socket и fork. Все проходят на текущей Anaconda.
Исходный M01 теперь возвращает предметные результаты, а не PermissionError.

Оригиналы sandbox.py и executor.py сохранены рядом как
*.before_stdlib_fix.txt. Их хеши совпадают со старым advanced_freeze.json.
Сравнение старой и новой заморозки показывает изменения только этих двух файлов.
Это раскрываемое исправление инфраструктуры, общее для всех M-архитектур;
исходное задание запрещало самостоятельно менять исполнитель. Пользователь
разрешил исправление; отдельного согласования преподавателя не было.

## Повторный технический запуск

```bash
python -m unittest discover -s tests -q
python -m advanced doctor
python -m advanced freeze --out runs/pilot_protocols/advanced_stdlib_fix_freeze.json
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m advanced run --freeze runs/pilot_protocols/advanced_stdlib_fix_freeze.json --ids M01,M04 --architectures single,fixed,coordinator --budgets 60000 --repeats 1 --out runs/advanced_technical_pilot_65k_stdlib_fix
```

6/6 эпизодов завершены. Модель Qwen3.5-4B, thinking выключен,
серверное окно 65536, общий бюджет 60000, один повтор.
Политики, модель, бюджет и исходные задачи не менялись.
Все шесть эпизодов — budget_exhausted, весь usage известен,
model_error/HTTP 400 нет. В M01 все схемы получили 0/12 открытых проверок,
в M04 schema_valid=false. Итоговую правильность M04 стенд не определяет.

В M01 больше нет инфраструктурного отказа чтения dataclasses. Например,
single теперь получает обычный результат solve с неверным отклонением
заказа out_of_stock, а не отказ импорта. Исправление среды не гарантирует
успеха модели: прежний бюджет по-прежнему исчерпывается до завершения.
Это технический пилот, не итоговые результаты; прежние неудачные пилоты
сохранены полностью и не заменены новыми эпизодами.

Финальная заморозка/полная матрица не запускались. Перед итогом нужно
явно принять протокол дополнительных блоков с наблюдаемыми ограничениями
или отдельно откалибровать общий бюджет, одинаковый для всех схем.
