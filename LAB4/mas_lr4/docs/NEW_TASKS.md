# Новые задания и сравнение на простой модели · версия 2.0

К исходному набору добавлены все 16 разработанных заданий: C01–C12, M01–M04.
Это часть обновлённой лабораторной. Основной набор D/T сохранён без изменений.
Работа индивидуальная, 3 недели, 10 баллов, без защиты. Отчёт: 1–2 страницы,
без титульного листа, ФИО и раздела о вкладе. Полные таблицы и трассы — отдельные файлы.

## Состав

| Набор | Задач | Открытых проверок | Назначение |
|---|---:|---:|---|
| D01–D25 | 25 | 250 | Разработка архитектур |
| T01–T50 | 50 | 500 | Исходное итоговое сравнение |
| C01–C12 | 12 | 72 | Связанные правила, один Python-модуль |
| M01–M03 | 3 | 46 | По 11 файлов, ошибки между модулями |
| M04 | 1 | 1 | Полный реестр и один небольшой открытый пример |
| Всего студенту | 91 | 869 | Уникальные задания и предметные проверки |

У M04 проверка формата не считается предметным тестом. Полный реестр — один
закрытый интеграционный тест с 40 решениями и 240 содержательными полями.
Это не 40 независимых тестов. Вход содержит 11925 физических записей,
11405 логических версий и 5600 событий в четырёх JSONL-файлах. Считать разрешено
программой; одинаковый инструмент доступен всем трём схемам. Сам объём файла
не доказывает, что модель прочитала его целиком в контексте.

## Модель и единые условия

Преподаватель выбирает реально доступную группе простую модель и точный API ID.
Укажите его в config.json, docs/extra_config.json и advanced/config.json.
Все роли всех схем одного сравнения используют эту же модель. Нельзя давать
координатору более сильную модель. Не выводите качество из названия модели.
Если отдельно исследуете ещё одну модель, выполните полную отдельную матрицу
и сравнивайте архитектуры прежде всего внутри каждой модели.

Сначала проверьте HTTP-провайдера, действительные usage, допустимые параметры,
размеры запросов и цену на dev. При необходимости преподаватель меняет общий
бюджет до финальной заморозки одинаково для всех схем. Значения 60000 в новых
конфигурациях — исходный протокол, а не измеренная потребность конкретной модели.
Учтите повторную передачу истории и кода. Если usage неизвестен, полный расход
и стоимость неизвестны; подставлять ноль нельзя. Логическое действие, запуск роли
и внутренний API-вызов — разные единицы, их нельзя складывать в одну метрику.

Гипотеза: ревью и разделение работы могут помогать при слабой модели, связанных
правилах и многомодульных ошибках. Это нужно проверить. Плата за сообщения и
координацию может перекрыть пользу. Победа MAS не является условием оценки.

## Реализация

Для D/T/C: maslab/student_policies.py, интерфейс описан в IMPLEMENTATION.md.
Для M: advanced/student_policies.py, перенесите обе политики на новый Engine.
Готовый single находится в advanced/policies.py. Общий BASE, исполнитель,
baseline, данные и счётчики менять нельзя; инструкции отдельных этапов задавайте
аргументом instruction в своей политике. Разрешённые изменения фиксируйте.

Fixed: programmer → reviewer → programmer → engine.finish(). Даже если первая
версия верна, все три этапа выполняются. Передайте замечания ревьюера явно.
Coordinator: coordinator_decision(feedback), проверка JSON и роли, затем
run_role('developer' или 'tester', instruction, max_turns). Координатор выбирает
следующую роль; сам не редактирует. Reviewer/tester могут проверять и сохранять
свои заметки, но не менять код/ответ. finish роли завершает её этап; окончательное
завершение эпизода — engine.finish(). У всех общий токеновый бюджет, 48 вызовов
модели и 80 инструментальных действий. Неверный JSON тоже расходует вызов.

Проекты: read_code, replace_files (полные тексты только перечисленных файлов),
run_tests, run_cases. Стандартная библиотека и классы разрешены, внешний ввод-вывод
запрещён. Контракт отличается от ограниченного Python для D/T/C.
Среда M: Linux, Python 3.11+, libseccomp и работающий изолированный исполнитель.
Проверено на Linux/Python 3.12. Если doctor не проходит, обратитесь к преподавателю
за общей средой; отключать изоляцию для модельного кода нельзя.

Реестр: read_corpus, search_corpus с пагинацией; run_program с кодом solve(data).
data['records'] содержит весь исходный корпус, data['task'] — метаданные задачи.
run_program выполняет программу на полном корпусе и сохраняет JSON допустимого
формата. Можно также submit_answer с готовым JSON. Открытый пример из examples.json
проверяется отдельно при run_tests и окончательном engine.finish(). Статус submitted и success=null не означают правильность полного ответа:
её проверяет преподаватель после заморозки всех запусков.
save_note/load_note/compact_notes доступны всем схемам; заметки и сокращение истории
относятся только к вызывающей роли. Передача другой роли должна быть явной.

## Запуск новых блоков

Все команды выполняются из корня распакованного комплекта. Настройка модели — PROVIDER.md.
Без обращения к модели:

```bash
python -m maslab doctor
python -m advanced doctor
python -m unittest discover -s tests -v
python -m maslab check C01
python -m advanced check M01
```

Ошибочные исходники C01/M01 намеренно не проходят все открытые случаи.
Политики сначала разработайте на dev; не подбирайте их по итогам C/M.
До итогового сравнения допускается отдельно обозначенный технический пилот
для проверки адаптера и общего бюджета. Сохраните его, укажите влияние на протокол.
Не переносите его цифры в итоговую таблицу и не выбирайте лучшие попытки.
Single можно проверить до написания двух политик:

```bash
python -m maslab freeze --config docs/extra_config.json --out extra_freeze.json
python -m maslab run --config docs/extra_config.json --freeze extra_freeze.json --split extra --ids C01 --architectures single --repeats 1 --out runs/extra_pilot
python -m advanced freeze
python -m advanced run --ids M01 --architectures single --repeats 1 --out runs/advanced_pilot
```

После любых разрешённых изменений — новая заморозка перед итоговым запуском.
Три схемы должны быть реализованы. Полный финальный протокол:

```bash
python -m maslab freeze
python -m maslab run --split test --out runs/final
python -m maslab freeze --config docs/extra_config.json --out extra_freeze.json
python -m maslab run --config docs/extra_config.json --freeze extra_freeze.json --split extra --out runs/extra
python -m advanced freeze
python -m advanced run --out runs/advanced
```

Исходный блок: 50 × 3 × 2 бюджета × 2 повтора = 600 эпизодов.
Новый C: 12 × 3 × 1 бюджет × 2 повтора = 72; M: 4 × 3 × 1 × 2 = 24.
Итого при стандартном протоколе — 696 итоговых эпизодов. Разработка и пилоты отдельно.
Общие лимиты новых блоков: C — 600 с/эпизод, 4000 выходных токенов/ответ;
M — 900 с/эпизод, 6000 выходных токенов/ответ. Выход входит в общий бюджет.
Запуск может потребовать существенных расходов: оцените их по реальному пилоту
до полной матрицы. Общий протокол группы назначает преподаватель до заморозки.

Для продолжения используйте ту же команду с --resume. Прерванный M-эпизод
сначала закройте явно, сохраняя исходные файлы:

```bash
python -m advanced close-interrupted --out runs/advanced --episode-id M01_single_b60000_r1 --reason "описание внешнего сбоя"
python -m advanced run --out runs/advanced --resume
```

Для D/T/C: python -m maslab close-interrupted runs/extra, затем точная команда --resume.
Прерванные/пропущенные эпизоды остаются в знаменателе; неизвестный расход неизвестен.
Нельзя незаметно повторять проигравшие эпизоды. Новый полный эксперимент храните отдельно.

## Анализ и сдача

Сохраните исходные шесть строк core (схема × бюджет), по три строки C и M01–M03,
M04 покажите отдельно. Приведите число успешных эпизодов/все запланированные,
долю исчерпаний бюджета, реальные токены, время, число вызовов и статус контроля.
До закрытой проверки у C/M01–M03 есть только открытое качество, у M04 — формат
и открытый пример. Не называйте их итоговой правильностью. Не смешивайте эти оценки.
Сравнивайте те же task/repeat при одинаковом бюджете; покажите совпадения и
расхождения ответов, включая single-only/MAS-only. 40 строк одного реестра и два
повтора не являются 40 независимыми задачами. Два повтора дают ограниченное основание
для обобщения, а программная обработка M04 не является чистым тестом окна контекста.

Разберите три трассы, включая межмодульную ошибку и M04: что передала роль,
что реально проверил инструмент, где ушёл бюджет. Полные таблицы — рядом с коротким PDF.
Сдайте обе student_policies.py, инструкции, три конфигурации, три freeze,
свои offline-сценарии, все папки runs/final, runs/extra, runs/advanced,
и README с командами и средой. Ключи, .env, эталоны и преподавательский пакет не сдавать.
