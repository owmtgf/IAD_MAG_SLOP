# Локальный dev-пилот

Модель: Qwen3.5-4B, точный API ID указан в трёх конфигурациях.
Endpoint: http://192.168.3.42:8000/v1 (vLLM, thinking отключён).
Для доступа к этому серверу в maslab/provider.py добавлен конкретный LAN-адрес
в разрешённые HTTP-хосты. Изменение общее для всех архитектур и блоков.
Учёт usage, лимиты и формат запросов сохранены.

Из корня mas_lr4:

```bash
python -m unittest discover -s tests -v
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m maslab run --split dev --ids D01 --architectures single,fixed,coordinator --budgets 6000 --repeats 1 --out runs/dev_smoke_4k
```

Это технический dev-пилот с окном сервера 4096, не итоговый эксперимент.
Финальная заморозка ещё не выполнена.

## Калибровка после технического пилота

После наблюдаемых HTTP 400 окно vLLM увеличено с 4096 до 16384.
Thinking остаётся отключённым. По рекомендации преподавателя на dev проверяются
два общих бюджета: 12000 и 24000, одинаковых для трёх архитектур.
Параметр budgets в config.json обновлён; в команде он также задан явно.

В обеих студенческих политиках исключено дублирование verified_report:
актуальный полный отчёт уже автоматически включается Engine в контекст роли.
При передаче сохранены сообщение роли и доступные поля идентификации артефакта.
Заключительный программист получает замечания ревьюера и контекст Engine.
Baseline, base.txt, счётчики и правила завершения не изменены.

```bash
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m maslab run --split dev --ids D01,D06,D11,D16,D21 --architectures single,fixed,coordinator --budgets 12000,24000 --repeats 1 --out runs/dev_calibration_12k_24k
```

30 эпизодов, один повтор; это разработка на dev, не итоговое сравнение.
Предыдущие технические пилоты сохранены в отдельных папках runs.

## Общая корректировка формата (dev, версия 2)

По результатам первого пилота модель систематически добавляла message к finish.
В prompts/base.txt добавлено явное различие между finish (только action) и
yield (action и message), отрицательный пример и указание исправлять отвергнутый
формат. Уточнение одинаково действует на single, fixed и coordinator в maslab.
Python-контракт и исходный текст инструкции сохранены; роли, лимиты, модель,
бюджеты и реализация политик во втором пилоте те же.

Это явно обозначенное отступление от исходного запрета менять base.txt,
принятое пользователем в ходе разработки. Отдельного согласования преподавателя
на эту корректировку нет. Изменение следует раскрыть в отчёте, включая оба пилота.
Оригинал общей инструкции сохранён в
runs/dev_calibration_12k_24k/base_before_format_fix.txt; исходный хеш есть в manifest.
Advanced Engine использует собственный BASE, на него это уточнение не влияет.

```bash
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m maslab run --split dev --ids D01,D06,D11,D16,D21 --architectures single,fixed,coordinator --budgets 12000,24000 --repeats 1 --out runs/dev_calibration_12k_24k_format_v2
```

Один повтор на условие: наблюдаемые изменения не отделяют полностью эффект
инструкции от вариативности модели. Итоговый test пока не запускался.

## Калибровка 24000 / 48000

```bash
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -m maslab run --split dev --ids D01,D06,D11,D16,D21 --architectures single,fixed,coordinator --budgets 24000,48000 --repeats 1 --out runs/dev_calibration_24k_48k_format_v2
```

Запуск выполнен без изменения инструкций, политик и конфигурации относительно
format_v2: новые бюджеты заданы аргументом CLI, имеющим приоритет над config.
После завершения 30 эпизодов рабочие budgets в config.json обновлены на
24000/48000. Это изменение произошло после пилота и не меняет его manifest.
Для точного воспроизведения его fingerprint нужно использовать конфигурацию
из manifest (там budgets 12000/24000) и CLI-аргумент 24000,48000.
Подробный анализ: runs/dev_calibration_24k_48k_format_v2/ANALYSIS.md.
Заморозки и итоговых test-запусков пока нет. Бюджеты дополнительных C/M
остаются 60000.

## Технический пилот C/M

Завершены 3 эпизода C01 и 6 эпизодов M01/M04 с бюджетом 60000, одним
повтором и окном 16384. Полные материалы: runs/extra_technical_pilot,
runs/advanced_technical_pilot и runs/pilot_protocols/TECHNICAL_PILOT.md.
Последний файл содержит команды, точные размеры отклонённых запросов
и причины остановок. Итоговая заморозка отложена до проверки большего окна.

Пилот повторён с серверным окном 65536: runs/extra_technical_pilot_65k и
runs/advanced_technical_pilot_65k, те же снимки и бюджеты. HTTP 400 устранены,
но на M01 обнаружен PermissionError при импорте dataclasses из Anaconda.
Подробности и диагностические выводы: runs/pilot_protocols/TECHNICAL_PILOT_65K.md.
До финальных M-запусков требуется совместимая с изоляцией среда Python 3.11+.

## Исправление Anaconda/stdlib и повторный M-пилот

В Landlock разрешены библиотечные пути текущего Python через sysconfig.
doctor дополнен реальным импортом dataclasses внутри worker. Все 63 теста
прошли, включая сохранение запретов внешнего чтения/записи/сети/процессов.
Подробности, команды и раскрытие изменения: runs/pilot_protocols/STDLIB_FIX.md.
Новый технический снимок — advanced_stdlib_fix_freeze.json в той же папке;
шесть эпизодов — runs/advanced_technical_pilot_65k_stdlib_fix.
Импорт исправлен, все эпизоды пока исчерпали бюджет. Финальная матрица
не запускалась; прежние технические пилоты сохранены.
