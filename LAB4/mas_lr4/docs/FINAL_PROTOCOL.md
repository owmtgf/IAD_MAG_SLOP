# Зафиксированный итоговый эксперимент

## Статус протокола

Это эксперимент по **изменённому протоколу**, а не воспроизведение исходных
условий задания. Конкретные бюджеты T 24000/48000 вместо 6000/12000 и
редактирование общего base.txt отдельно с преподавателем не согласованы.
Рекомендация провести калибровку не означает согласования этих изменений.
На dev вход около 2000 токенов на запрос приводил к исчерпанию исходных
лимитов до завершения процесса; повторяющийся finish с message отклонялся
валидатором. В ответ увеличены бюджеты и уточнён общий формат finish/yield.
Изменения применены ко всем схемам до freeze; baseline-код и данные сохранены,
но общая инструкция модели отличается от исходной. Выводы относятся именно
к этой версии протокола. Пилоты до/после приложены отдельно.

## Условия

До test выбраны: Qwen3.5-4B через vLLM на RTX 5070, BF16,
http://192.168.3.42:8000/v1, окно 65536, thinking выключен,
temperature=0, send_seed=false, seed=41729. Точный API ID — в трёх config.
Один модельный запрос одновременно, роли и эпизоды последовательно.

Гипотеза: ревью и координация могут помогать исправлению, но расход контекста
и ошибки передачи/формата могут перекрывать пользу. Победа команды не требуется.
Основная метрика core — корректное завершение текущего кода в пределах бюджета;
открытое качество C/M и формат M04 показываются с их ограничениями отдельно.

| Блок | Задачи | Схемы | Бюджеты | Повторы | Эпизоды |
|---|---:|---:|---|---:|---:|
| core/test | 50 | 3 | 24000, 48000 | 2 | 600 |
| extra/C | 12 | 3 | 60000 | 2 | 72 |
| advanced/M | 4 | 3 | 60000 | 2 | 24 |

Лимиты ответа/эпизода: core 1800 токенов/300 с, C 4000/600 с,
M 6000/900 с. Общий бюджет суммирует вход и выход всех ролей.
Максимум 48 модельных вызовов, 80 инструментальных действий. Fixed: этапы
10/6/12 действий; coordinator: до 10 решений и до 3 действий на делегирование.
Никаких скрытых повторов. Все запланированные эпизоды остаются в знаменателе.

## Изменения комплекта, сделанные до финала

- Общий адаптер разрешает HTTP к конкретному LAN-адресу.
- Общая инструкция maslab уточняет формат finish/yield; сохранены пилоты до/после.
- Sandbox учитывает stdlib/platstdlib текущего Python; doctor проверяет импорт
  dataclasses внутри изоляции. 63 offline-теста подтверждают работу среды и
  запреты внешнего чтения, записи, сети и создания процессов.
- Основные бюджеты откалиброваны на dev до 24000/48000.

Это явно раскрываемые изменения относительно исходных ограничений задания,
принятые пользователем без отдельного согласования преподавателя. Baseline,
исходные задачи и ожидаемые ответы не редактировались. Все пилоты сохранены
отдельно. Низкие результаты технических C/M-пилотов приняты как известное
ограничение; дальнейшей подстройки под эти наборы перед test не проводилось.

## Запуск

Из корня mas_lr4, после создания freeze.json, extra_freeze.json и
advanced_freeze.json:

```bash
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -u scripts/run_final.py
```

Launcher запускает блоки последовательно. Полные данные — runs/final,
runs/extra, runs/advanced. Журналы процесса — runs/final_core.log,
runs/final_extra.log, runs/final_advanced.log. Состояние процесса —
runs/final_pipeline_status.json; это не замена подсчёту завершённых эпизодов.

После заморозки код, инструкции, данные и конфигурации не менять.
При прерывании сначала сохранить файлы и закрыть прерванный эпизод по
процедуре лабораторной; только затем явно продолжить тот же эксперимент:

```bash
MAS_LLM_BASE_URL=http://192.168.3.42:8000/v1 python -u scripts/run_final.py --resume
```

Скрипт сам не закрывает и не повторяет прерванные/неуспешные эпизоды.
Не запускать второй экземпляр одновременно с работающим первым.
