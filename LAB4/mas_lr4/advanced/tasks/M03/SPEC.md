# M03 — Архив документов с делегированными правами

Исправьте реализацию небольшого сервиса. В проекте уже реализованы документы,
ACL, цепочки делегирования, версии, квоты, идемпотентность и транзакции, но
некоторые правила нарушены. Можно редактировать только Python-файлы из
`starter/app`, перечисленные в `task.json`. Используйте только стандартную
библиотеку Python. Точка входа: `app.api.solve(data) -> dict`.
Каждый вызов независим: никакое состояние не переносится между вызовами.
Не изменяйте входной объект. Не читайте файлы тестов и не используйте сеть.

## Вход и допустимые размеры

Вход — JSON-объект с обязательными массивами `tenants` и `principals`.
Массивы `documents` и `operations` необязательны и по умолчанию равны `[]`.

* Tenant: `{"id":"t","quota":12}`. Квота — целое неотрицательное число байтов.
* Principal: `{"id":"a","tenant":"t"}`. Tenant должен существовать.
* Начальный документ: `{"id":"d","tenant":"t","owner":"a","text":"abc","acl":[...]}`.
  Владелец принадлежит tenant документа. Начальная версия всегда 1.
* Элемент начального ACL: `{"principal":"b","allow":["read"],"deny":[]}`.
  Principal существует и принадлежит тому же tenant. Отсутствующий ACL — пустой;
  отсутствующие `allow`/`deny` — пустые массивы. Один principal встречается в ACL
  не более одного раза.

Начальные ID уникальны в своих пространствах. ID документов глобальны для
всех tenant. Начальные документы не удалены, начальные делегирования отсутствуют,
начальное использование квоты допустимо. Все строки — корректный Unicode без
суррогатов. Права принадлежат множеству `read`, `write`, `share`; массивы прав
не содержат повторов. `rights` может быть пустым. Поля операций имеют указанные
ниже типы; неизвестных операций и лишних полей нет. Значения actor/recipient/
principal могут обозначать неизвестного principal, чтобы проверить ошибки.
Версии и `expected` — положительные целые числа. Поля `via` и `key` при наличии
являются строками (не null).

Не более 8 объявленных principal, 8 различных ID документов во всём входе,
8 различных ID делегирований и 30 операций, считая `atomic` и все его дочерние
операции. Не более 3 tenant. `atomic` не вложены друг в друга. В одном `atomic`
имена создаваемых savepoint различны; допускается несколько rollback к одному
имени. Порядок входных операций существенен.

## Права и изоляция

Владелец имеет неявные `read`, `write`, `share`. Прямые права — объединение
прав владельца и `allow` из текущего ACL за вычетом `deny`. Эффективные права —
объединение прямых прав и прав всех активных делегирований, полученных данным
principal для данного документа, затем вычитание текущего `deny`. Таким образом,
`deny` побеждает и владельца, и прямое разрешение, и любое делегирование.

Документ чужого tenant, отсутствующий или удалённый документ для любой операции
над существующим документом даёт `document_not_found`, даже если principal не
имеет прав. Создание использует глобальное пространство ID: ID удалённого или
чужого документа тоже занят. При создании owner — actor, tenant — tenant actor.
ACL, версии и делегирования сами по себе не меняют tenant/owner.

Любое успешное изменение ACL, создание/отзыв делегирования, создание/удаление
документа немедленно влияет на последующие проверки прав. Кэш допустим, но
поведение не должно зависеть от того, были ли права уже прочитаны.

## Операции

Ниже `D` обозначает результат `{"id":id,"owner":owner,"text":text,"version":v}`.
Изменяющие операции `create`, `write`, `delete`, `acl`, `delegate`, `revoke`
могут иметь поле `key`; его точный смысл описан ниже.

| op и поля | Семантика и успешный результат |
|---|---|
| `create`: actor, id, text | Новый документ версии 1 с пустым ACL. Результат D. |
| `read`: actor, id, необязательный version | Нужен `read`. Без version вернуть текущую версию; с version — соответствующий исторический текст и эту версию. Результат D. |
| `write`: actor, id, text, expected | Нужен `write`. expected равен текущей версии. Всегда добавить следующую версию, даже если текст идентичен. Результат D новой версии. |
| `delete`: actor, id, expected | Нужен `write`. Добавить следующую версию с text=null, пометить документ удалённым. Результат `{"id":id,"deleted":true,"version":v}`. |
| `acl`: actor, id, principal, необязательные allow/deny | Нужен `share`. Полностью заменить запись ACL указанного principal; пустая запись сохраняется. Результат `{"id":id,"principal":principal,"allow":[...],"deny":[...]}`. |
| `delegate`: actor, id, grant, recipient, rights, необязательный via | Нужен `share`. Создать новое делегирование. Результат `{"grant":grant,"revoked":false}`. |
| `revoke`: actor, id, grant | Нужен `share`; любое лицо с этим правом может отозвать любое делегирование этого документа. Повторный отзыв успешен. Результат `{"grant":grant,"revoked":true}`. |

История сохраняет все версии, начиная с 1, включая одинаковые тексты и
финальную версию удаления. Читать историю удалённого документа нельзя.
Квота tenant равна сумме длин UTF-8 текущих текстов его неудалённых документов.
История, ACL, делегирования и удалённые документы квоту не занимают.
Обновление заменяет стоимость старого текста стоимостью нового; удаление
освобождает квоту. Равенство лимиту допустимо.

### Делегирование

ID grant глобален и остаётся занят после отзыва. Без `via` источник прав —
**прямые** права actor; они должны содержать `share` и все запрошенные `rights`.
Полученные делегированные права не позволяют создавать новое корневое
делегирование без соответствующих прямых прав.

При наличии `via` указанное делегирование должно существовать, быть активным,
принадлежать этому документу и иметь recipient=actor. Источник прав — пересечение
его `rights` с текущими эффективными правами actor. Источник должен содержать
`share` и все запрошенные права. Новое делегирование сохраняет ссылку parent=via.
Новый grant ссылается только на уже существующий grant, поэтому циклов нет.

Делегирование активно, если оно и все его предки не отозваны. Отзыв предка
немедленно выключает все ветви потомков; собственный флаг `revoked` у потомков
при этом не изменяется. Изменение ACL влияет на текущие права получателя,
но не меняет сохранённые права grant и не отзывает ранее созданные дочерние
grant. При необходимости отзыва всей ветви используется `revoke`.

### Идемпотентность

Пространство ключей — пара `(actor, key)`, общее для всех изменяющих операций
этого actor. После успешной операции сохраняются исходный запрос без `key` и
глубокая копия результата. Эквивалентность запросов определяется JSON-значением:
порядок ключей объекта несущественен, порядок элементов массивов существенен;
отсутствующее поле отличается от присутствующего пустого поля. При повторе
эквивалентного запроса вернуть сохранённый результат без повторного изменения
и **до** проверки существования документа, текущих прав, версии и квоты.
Это возможно и после удаления документа или отзыва прав. Другой запрос с той
же парой даёт `idempotency_conflict`. Ошибки не запоминаются. Операции без key
не запоминаются. Проверка существования actor предшествует проверке ключа.

## Транзакции и savepoint

`{"op":"atomic","operations":[...]}` исполняет дочерние операции по порядку.
Все изменения документов, истории, ACL, grants, запомненных ключей и кэша
относятся к общей транзакции. Успех: `{"ok":true,"results":[...]}`.
При первой ошибке восстановить состояние перед atomic, прекратить исполнение
и вернуть `{"error":"transaction_failed","index":i,"cause":ошибка,
"results":[успешные результаты до i]}`. Индекс i начинается с 0.
Уже выданные результаты описывают выполнение и не переписываются после отката.
Пустой atomic успешен.

Внутри atomic дополнительно доступны:

* `{"op":"savepoint","name":"s"}` — сохранить полную независимую копию
  состояния в данной точке; результат `{"savepoint":"s"}`.
* `{"op":"rollback","name":"s"}` — восстановить сохранённое состояние,
  включая ключи идемпотентности, и удалить все более поздние savepoint.
  Сам s сохраняется и может быть использован снова. Результат
  `{"rolled_back":"s"}`. Предыдущие результаты остаются в массиве results.

Неизвестное или уже удалённое имя даёт `savepoint_not_found` и проваливает
весь atomic. Savepoint не существуют вне своего atomic. Оба вида управляющих
операций вне atomic дают `invalid_context` и не требуют actor.

## Ошибки и порядок проверок

Ошибка — `{"error":code}`, кроме `version_conflict`, где дополнительно
`"actual":текущая_версия`, и описанного `transaction_failed`.
Первая нарушенная проверка в следующих списках определяет результат.

1. Для любой обычной операции: известность actor (`actor_not_found`), затем
   replay/конфликт идемпотентности.
2. `create`: занятость глобального ID (`document_exists`), затем квота
   (`quota_exceeded`).
3. Все прочие обычные операции: видимость документа (`document_not_found`),
   затем нужное эффективное право (`permission_denied`).
4. `read`: наличие запрошенной исторической версии (`version_not_found`).
5. `write`/`delete`: expected (`version_conflict`); только у write затем квота
   (`quota_exceeded`).
6. `acl`: существование principal (`principal_not_found`), затем тот же tenant
   (`tenant_mismatch`), затем замена ACL.
7. `delegate`: существование recipient (`principal_not_found`), его tenant
   (`tenant_mismatch`), занятость grant (`grant_exists`), корректность via,
   если задан (`invalid_parent`), затем достаточность источника прав
   (`permission_denied`).
8. `revoke`: существование grant именно у этого документа (`grant_not_found`).

Ошибочная операция не изменяет наблюдаемое состояние и не добавляет memo.
Состояние частично успешного atomic целиком откатывается.

## Выход

`{"results":[результат каждой верхнеуровневой операции],"state":{...}}`.
Ключи JSON-объектов сравниваются без учёта порядка. Массивы сравниваются точно.
`state` содержит:

* `documents`, отсортированный по id, включая удалённые:
  `{"id":...,"tenant":...,"owner":...,"text":строка_или_null,
  "version":... ,"deleted":bool,"history":[{"version":1,"text":...},...],
  "acl":[{"principal":...,"allow":[...],"deny":[...]},...]}`.
  history упорядочена по возрастанию версии, ACL — по principal.
* `grants`, отсортированный по id:
  `{"id":...,"doc":...,"issuer":...,"recipient":...,"rights":[...],
  "parent":строка_или_null,"revoked":bool}`.
* `usage`, объект tenant ID → фактически занятые UTF-8 байты, включая нули.

Все массивы прав в результатах и state сортируются лексикографически
(`read`, `share`, `write`). Имена tenant, principal, doc и grant сортируются
обычным лексикографическим порядком строк Python. Кэш и memo не выводятся.
Видимые примеры находятся в `visible.json`; скрытые проверки используют те же
правила и указанные ограничения.
