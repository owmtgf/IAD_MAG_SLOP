# ЛР4. Кто лучше исправляет код: один агент или команда?

Версия 2.0: добавлены C01–C12 и M01–M04, новый HTTP-запуск проектов/реестра,
явный контракт Python и контроль новых блоков. Всего 91 публичное задание,
869 открытых предметных проверок. Сначала прочитайте docs/NEW_TASKS.md:
оно дополняет исходный блок ниже. Итог по умолчанию: 600 core + 72 C + 24 M
= 696 эпизодов на одной согласованной модели. Преподаватель выбирает простую
доступную модель и проверяет бюджет до выдачи.

Обязательная центральная работа курса MAS. Индивидуально, 3 недели, 10 баллов.
Задание: `docs/MAS_LR4_Task.pdf`. Краткий шаблон отчёта: `docs/REPORT_TEMPLATE.pdf`.

Вы сравните три способа организации одной и той же LLM на исправлении программ:
готовый одиночный агент; ваш фиксированный процесс; ваша команда с координатором.
Оцениваются реализация и честность эксперимента, а не обязательная победа команды.

Эпизод - один запуск одной архитектуры на одной задаче с заданным бюджетом.
Dev - набор для разработки, test - набор для итогового сравнения; baseline -
готовый одиночный агент. Freeze - фиксация версии кода, инструкций, данных и настроек
перед test. Токены - единицы текста на входе и выходе модели; usage - фактический
расход токенов, сообщённый провайдером. Общий бюджет эпизода делят все роли.

## Что уже готово

- `maslab/policies.py`: одиночный агент с повторными исправлениями и тестами.
- `maslab/engine.py`: общие инструменты, независимая проверка, логи, бюджет всех ролей.
- `maslab/student_policies.py`: два места TODO для вашей реализации.
- `prompts/`: начальные инструкции ролей, которые вы доработаете на dev.
- `data/dev/`: 25 задач, 250 открытых проверок с ответами.
- `data/test/`: 50 итоговых задач, 500 открытых проверок с ответами.
- `tests/`: 48 автономных проверок стенда; они не входят в 869 проверок задач.

Одна задача - один небольшой Python-модуль с ошибкой и функцией `solve(data)`.
В исходном блоке это 75 разных программ, а не варианты одной формулы с другими числами.
У каждой задачи `task.json` (условие), `main.py` (ошибочный исходник), `tests.json`
(10 входов и ожидаемых результатов). Правильный код в студенческом архиве отсутствует.
В 25 итоговых задачах исходник содержит два дефекта, в остальных - один.

## Быстрый старт без расходов на модель

Распакуйте архив. Откройте терминал в папке `mas_lr4`.
Нужен Python 3.10+; сторонние Python-пакеты не нужны. Проверено на Linux/Python 3.12.

```bash
python -m maslab doctor
python -m unittest discover -s tests -v
python -m maslab check D01
```

На системах, где команда называется `python3`, замените `python` во всех командах.
`doctor` не вызывает LLM. Исходник D01 намеренно не проходит часть проверок.
Заглушки двух ваших архитектур намеренно содержат `NotImplementedError`.

## Первый реальный запуск

1. Настройте провайдера по `docs/PROVIDER.md`. Укажите модель в `config.json`.
2. Выполните маленький запуск готового baseline:

```bash
python -m maslab run --split dev --ids D01,D06,D11,D16,D21 --architectures single --budgets 6000 --repeats 1 --out runs/baseline_pilot
```

3. Откройте `runs/baseline_pilot/summary.json`, `results.csv` и любой `trace.jsonl`.
4. Реализуйте две функции в `maslab/student_policies.py` по `docs/IMPLEMENTATION.md`.
5. Проверьте три схемы на dev. Настройка на итоговых test запрещена.

```bash
python -m maslab run --split dev --ids D01,D06,D11,D16,D21 --architectures single,fixed,coordinator --budgets 6000 --repeats 1 --out runs/three_schemes_pilot
```

Эти две команды действительно обращаются к вашей модели и могут расходовать деньги.
API-ключ храните только в переменной окружения, не в коде и не в отчёте.

## Итоговое сравнение

Зафиксируйте реализацию после dev. До заморозки согласуйте с преподавателем модель
и общий протокол группы. Значения по умолчанию: 6000 и 12000 токенов, два повтора.

```bash
python -m maslab freeze
python -m maslab run --split test --out runs/final
python -m maslab summary runs/final
```

Полный запуск: 50 задач × 3 схемы × 2 бюджета × 2 повтора = 600 эпизодов.
Его продолжительность и стоимость зависят от провайдера и числа вызовов.
Не запускайте 600 эпизодов до маленького пилота. Оцените расход по его реальным usage.

`freeze.json` фиксирует хеши кода, инструкций, данных и конфигурации.
После freeze не меняйте их. Новая реализация требует нового dev-цикла и отдельного
явно обозначенного эксперимента; нельзя выбрать лучшую попытку по test.

Возобновить тот же запуск после завершённых эпизодов:

```bash
python -m maslab run --split test --out runs/final --resume
```

Если процесс прервался внутри эпизода, сначала выполните:

```bash
python -m maslab close-interrupted runs/final
python -m maslab run --split test --out runs/final --resume
```

Прерванный эпизод сохранится как неуспех с неизвестным полным расходом. Он не будет
незаметно запущен заново. Правила повторного эксперимента - в `docs/PROTOCOL.md`.
